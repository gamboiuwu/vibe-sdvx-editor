1. Overview

vibe-editr is a browser-based chart editor for the rhythm game format Sound Voltex (SDVX / KSH / KSON). It lets you create, edit, and export charts with a fully visual timeline, 3D game preview, and real-time audio playback.

No installation is required — open index.html in any modern browser (Chrome, Edge, or Firefox recommended).

vibe-editr saves nothing to a server. All files stay on your computer. Autosave downloads a .ksh file locally on the interval you configure in Preferences.

2. Interface Layout

Top Menu Bar

The menu bar at the top contains all primary menus: File · Edit · Chart · View · Settings · Window. Clicking any menu label opens its dropdown. Hovering moves between menus without clicking.

The top-right corner always shows quick-access buttons:

  • ✦ Edit — Switch to Edit-only view
  • ⧉ Split — Side-by-side Edit + 3D Preview
  • ▶ Preview — Full-screen 3D Game Preview
  • ▶ Play — Play / Stop (turns red while playing)
  • Error badge — Click to view any runtime errors

Tab Bar

Below the menu bar, open charts appear as Chrome-style draggable tabs. Click a tab to switch charts. Drag to reorder. Click ✕ to close. A + New button opens a blank chart.

Toolbar

The tool palette sits below the tabs. Select a tool by clicking or pressing its keyboard shortcut.

Three-Panel Edit Layout

  • Left panel — Song metadata (title, artist, BPM, offset, jacket) and camera parameters
  • Center — The main chart canvas. Notes scroll top-to-bottom, measures left-to-right in columns.
  • Right panel — FX Chain, BPM/Time Sig events, and the keyboard shortcut reference

Status Bar

At the bottom of the chart canvas: current Tick, Measure, Beat, active Tool, selection range, and a reminder that C opens the context menu.

3. Tabs & Files

Opening Files

  • File → New Chart — blank chart in a new tab
  • File → Open .ksh… — import a KSH chart file
  • File → Open .kson… — import a KSON chart file
  • File → Open Folder… — open an entire chart folder; each chart gets its own tab

Exporting

  • File → Export KSH — download the chart as a .ksh file
  • File → Export KSON — download as JSON-based .kson
  • Ctrl+S — quick-export as KSH

Loading Audio

Go to Chart → Load Audio File… and choose an OGG, MP3, or WAV file. The audio stays attached to that tab. Audio playback is always at 1.0× speed regardless of HiSpeed setting.

5. Note Types

BT (Button) Notes

Four lanes: A B C D (left to right). Chip notes are short; hold notes are drawn as tall rectangles. In the KSH format: 1 = chip, 2 = hold-active, 0 = empty.

FX (Effect) Notes

Two wide lanes: FX-L (left) and FX-R (right). Each covers two BT-lane widths. Long FX holds show their assigned effect name. In KSH format: 2 = chip, 1 = hold-active.

FX Chain Effects

Use the right panel to assign audio effects to the FX-L and FX-R hold lanes. Click + Add Effect and choose from: Retrigger, Gate, Flanger, PitchShift, BitCrusher, Phaser, Wobble, TapeStop, Echo, SideChain.

6. Lasers (VOL)

Lasers are continuous curves drawn across the lane. Left laser = blue. Right laser = pink.

Placing Lasers

  1. Select the 4 or 5 laser tool.
  2. Click on the chart to begin a new laser section at that position.
  3. Drag to draw the laser path. Release to finish that segment.

Slams

A slam is a near-instant jump (≤ 6 ticks apart). It renders as a right-angle L-shape connecting two points. The audio "slam" sound triggers at these positions.

Wide Lasers

Enable Settings → 2× Wide Lasers to use the full-width laser mode (laserrange=2x in KSH).

7. Selection & Clipboard

Making a Selection

Middle-mouse drag — drag across the chart to select a tick range. A cyan highlight appears. A single middle-mouse click (no drag) just moves the playhead.

Selection Operations

  • Ctrl+C — Copy all notes in the selection
  • Ctrl+X — Cut (copy + delete)
  • Ctrl+V — Paste at playhead position
  • Esc — Clear selection

Context Menu (C or Ctrl+RClick)

Press C anywhere on the chart canvas to open the context menu. Available actions:

  • Cut / Copy / Paste
  • Modify Style → Mirror: Mirror All, Mirror BT, Mirror FX, Mirror VOL
  • Adjust Speed: ½× slower (expands tick positions) or 2× faster (compresses)

Playing a Selection

With a region selected, press Space to play only that range. Playback stops automatically at the end of the selection.

8. Playback & Audio

  • Space — Play from cursor / Stop (or play selection if one is active)
  • Home — Jump to measure 1
  • End — Jump to end of chart
  • ← → — Scroll one column left/right
  • Ctrl+←→ — Scroll multiple columns
  • PgUp / PgDn — Jump forward/backward by screen

HiSpeed

The HiSpeed slider (View menu) controls visual scroll density — how many measures fit on screen at once. Range: 0.2 – 10.00. Audio always plays at real tempo regardless of HiSpeed.

Tick Sound

Enable Settings → Enable Tick Sound to hear a click on every BT chip during playback.

9. View Modes

Edit View

Full-width top-down chart editor. Multiple columns of measures scroll horizontally.

Split View (default)

Edit canvas on the left, 3D Game Preview on the right simultaneously. Adjust the split ratio via Window → Split View Options. You can also change the number of visible lanes from that panel.

Game Preview

Full-screen 3D lane perspective — the same look as the actual game. The lane uses a trapezoidal perspective projection with scoring overlay (score, chain, grade).

Editing Inside the Preview

Right-click (or press C) on the Game Preview to open its context menu, then choose ✏ Edit Chart in Preview. An edit toolbar appears at the top. Click on the 3D lane to place BT or FX chips directly. Choose ✕ Exit Edit or Esc to return to preview-only mode.

10. History & Undo

Undo / Redo

  • Ctrl+Z — Undo last action
  • Ctrl+Y — Redo

History Panel

Open via Window → History & Timeline. A floating, resizable, draggable panel lists every edit action with its measure number. The current state is highlighted in blue. Click any past state to jump directly to it (like Photoshop's History panel). Future (undone) states appear dimmed.

The maximum number of history states is set in Preferences → History → Max history states (default: 100).

12. Exporting

KSH Format

KSH is the text-based chart format used by KShootMania and most SDVX tools. It uses 192 ticks per measure (48 per beat). Export via File → Export KSH or Ctrl+S.

KSON Format

KSON is the modern JSON-based format with richer camera and effect data. Export via File → Export KSON.

Always verify exported charts in KShootMania or USC before submitting. Laser timing, BPM changes, and hold edges should be spot-checked after export.

v0.0.79Declared-vs-Measured Level Check — catch a mislabelled difficulty before you ship it

  • addChart Statistics now reconciles the level you typed with the level you actually made. Every chart carries a hand-typed declared level in its metadata (meta.level, 1–20), and — since v0.0.78 — a measured honest level read straight from the six radar axes. A new line directly under the Est. level readout in the 📊 Chart Statistics modal compares the two: a matched chart shows a quiet green ✓ declared 15 matches measured 15, a mislabelled one flags the gap in colour — e.g. ⚠ declared 15 vs measured 18 (+3) — likely under-rated. A positive delta means the chart plays harder than its label (sandbagging players); a negative delta means it plays easier.
  • addAlso a pre-flight warning, so it is caught before export. Both the Chart Validity Checker and the Export Validator now carry a warn-only “Declared level ≈ measured” row that flags when the two are three or more levels apart, beside the existing “Level is 1–20” range check. It only ever warns — a deliberate off-label chart still exports — but a typo like a “12” that plays like a “17” no longer slips through silently.
  • addRender-only, one source of truth. Backed by a new DOM-free, unit-tested chart.levelMatchCheck(declared, raw) that reuses chart.honestLevelEstimate internally (so the measured half can never drift from the radar or the level readout it sits under). Guarded end-to-end: a note-less chart reports no data, a chart with no valid declared level reports no declared level, and empty/NaN/negative inputs never throw. Verified with 24 Node unit tests and two real-browser runs (an under-rated chart lights the red warning with the exact delta, an exact match shows the green tick), zero JS errors. The chart is never mutated.

v0.0.78Honest Level Estimate — the six measured axes reduced to one SDVX level

  • addChart Statistics now answers “what level did I just make?” from the measured axes. The v0.0.77 Honest Radar drew the six genuinely-measured difficulty numbers as one shape; a new Est. level line sits directly under it in the 📊 Chart Statistics modal and reduces those same six spokes to a single estimated SDVX level 1–20, names the axis driving it, and colours it on the same calm-green → hot-red ramp. It is deliberately not the volatility heuristic buried in the Density tool (which scores column variance and raw note/VOL counts) — it reads only the honest measured axes, so the headline number and the radar shape can never disagree.
  • addPeak-weighted, because a level tracks the hardest thing you must do. The estimate is composite = 0.6·(hardest axis) + 0.4·(mean of all axes) on the shared 0–100 scale where ~100 = “Extreme for that axis”, mapped linearly onto 1–20. A chart Extreme on every axis lands at 20, a one-dimensional gimmick sits mid-scale rather than topping out, and a note-less chart shows no level at all rather than a false “1”. A Beginner / Intermediate / Advanced / Expert / Extreme band reads it at a glance, and the hover tooltip shows the exact composite arithmetic — it is honestly labelled an estimate, not a verdict.
  • addRender-only, one source of truth. Backed by a new DOM-free, unit-tested chart.honestLevelEstimate(raw) that reuses chart.honestRadarProfile internally (so the level is literally a reduction of the polygon the radar draws), plus a shared chart.honestLevelBand(level) for the label and colour. Guarded end-to-end (NaN/negative/undefined axes degrade to 0, never throw; over-anchor inputs clamp at 20); the chart is never mutated. Verified with 28 Node unit tests and a real-browser run: an empty chart shows “—”, a 16th single-lane stamina chart reads level 17 Expert with zero JS errors.

v0.0.76Knob Load — the honest Tsumami / laser-density number, the fifth physical-difficulty axis

  • addChart Statistics now scores the VOL knobs — the axis every other number ignored. The four honest difficulty axes so far — the Green# reading window, Peak NPS, Peak Jack and Hand Balance — all measure your fingers on the BT/FX buttons, and every one of them deliberately excludes the lasers as “continuous knob motion, not a press.” That left a whole third of an SDVX chart — the Tsumami knobs — with no honest difficulty number anywhere (the radar’s TSUMAMI vertex is a normalised, curve-shaped polygon value, not a measured per-second figure). A new Knob Load (per second) row in both the 📊 Chart Statistics modal and the Tools-Hub Chart Statistics tool finally puts a real figure on it.
  • addCounts what the wrist actually does, not how long a laser is. A slow laser line is trivial; difficulty is how many discrete knob actions you must execute per real second. Knob Load counts three: a grab (catching the knob at a section start), a slam (a near-instant flick, using the same slam convention as import so the count can’t drift), and a reversal (an interior vertex where the knob changes direction). A vertex that is already a slam isn’t double-counted — the flick is the action. The busiest one wall-clock second sets the peak, banded at a glance — Light, Moderate, Busy, Heavy, Extreme — with the slam and reversal counts shown alongside.
  • addBPM-independent, render-only, one source of truth. Backed by a new DOM-free, unit-tested chart.knobStress(opts) that stamps every knob action to seconds through the same tickToSeconds time model the C-Mode scroll, the audio path and chart.notesPerSecond all use, then slides the same provably-exact 1-second window — so a slam storm at 240 BPM honestly outscores the identical tick pattern at 120. A shared chart.knobDifficultyBand(peakKps) drives the label and colour so the modal and the tool can never disagree. computeChartStats folds it in beside Hand Balance (guarded so a plain-object caller degrades to zero, never throws). The chart is never mutated.
